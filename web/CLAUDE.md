# web/CLAUDE.md：首爾旅遊攻略網站

> 本檔是「攻略網站」子專案的規格書。任何 AI 要修改 `web/` 或 `docs/` 之前，必須先讀完本檔；要修改 `wiki/` 內容時，以根目錄的 [`CLAUDE.md`](../CLAUDE.md) 為準。
> 分工：**根目錄 CLAUDE.md 管「攻略怎麼寫」，本檔管「攻略怎麼呈現」。**

---

## 1. 目的

把 `wiki/` 的 Markdown 攻略**編譯成給一般讀者看的靜態網站**：

1. **好讀**：手機、電腦都能看，連結可點，警示與待查證有醒目標示。
2. **好找**：依分類、標籤瀏覽，全文搜尋（中文、韓文、英文別名都能搜）。
3. **零依賴**：只用 Python 標準函式庫建置，網站可以直接雙擊開啟，也能放上 GitHub Pages。
4. **內容與呈現分離**：網站永遠由 `wiki/` 自動產生。**網站上的錯誤要回去改 `wiki/`，不改 HTML。**

不做：線上編輯、登入、資料庫、網頁上呼叫 AI、載入外部圖片或 CDN。

## 2. 使用方式

```bash
python web/build.py      # 讀 wiki/，輸出到 docs/
```

- 本機瀏覽：雙擊 `docs/index.html`。
- 線上瀏覽：GitHub repo → Settings → Pages → `main` 分支、`/docs` 資料夾。
- **每次收錄、lint 或修改 wiki 後都要重新 build**，並把 `docs/` 一起 commit。

## 3. 網頁風格

定位：**乾淨、溫暖、像旅遊手帳**。讀者常在當地用手機查，字要大、對比要夠。

| 變數 | 淺色 | 深色 | 用途 |
|------|------|------|------|
| `--bg` | `#fcfaf6` 米白 | `#16181d` | 背景 |
| `--panel` | `#f4efe6` | `#1e2128` | 側欄、資訊卡 |
| `--accent` | `#1d5c63` 青綠（取自韓國傳統建築的丹青色） | `#7cc4c2` | 連結、標題線 |
| `--warn` | `#b8392f` 朱紅 | `#e8826b` | ⚠️ 待查證、斷鏈、已歇業 |

- 字體：內文 Noto Sans TC／微軟正黑體，標題 Noto Serif TC／宋體。不從 CDN 載入。
- 版面：桌機為「側欄＋內容＋本頁目錄」三欄；寬度 < 760px 時側欄收成 ☰ 選單。
- 支援深淺色模式（右上角按鈕），預設跟隨系統。
- 顏色只用 `web/static/style.css` 裡 `:root` 的變數。

## 4. 頁面架構

```
docs/
├── index.html      首頁：統計＋攻略總覽（wiki/overview.md）＋分類卡片＋最近紀錄
├── all.html        全部頁面（wiki/index.md）
├── tags.html       標籤頁
├── log.html        操作紀錄（新的在上）
├── c/<分類>.html    分類頁：依更新日期排序的卡片
├── p/<頁面>.html    攻略頁
└── assets/         style.css、app.js、search-index.js
```

**攻略頁由上到下**：麵包屑 → 標題 → 徽章（類型、可信度、更新日期、資料確認日期）→ **資訊卡**（韓文、類型、風格、區域、交通、時間、價格、門市、別名、標籤、來源）→ 內文 → 相關頁面 → 反向連結。右側為本頁目錄。

資訊卡的欄位直接讀自 frontmatter（見根目錄 CLAUDE.md 第 6 節），欄位裡的 `[[連結]]` 會變成可點的連結。

## 5. 內容格式要求

網站依賴以下格式，寫錯會顯示不完整：

- frontmatter 一行一個欄位；清單寫成單行 `[a, b]`；含逗號或 `[[ ]]` 的值加雙引號。
- `title`、`type` 必填；`checked` 會顯示成「資料確認」日期。
- 分類頁與首頁的一句話摘要取自 `wiki/index.md`，**新增頁面一定要更新 index.md**。
- 特殊標記：`> ⚠️ 待查證：…`、`> ⚠️ 已歇業…` 顯示為朱紅警示框；`> 💡 …` 顯示為提示框；「（我的推測）」以淡色斜體顯示。
- 支援的 Markdown：標題、粗體、斜體、清單（可巢狀）、核取方塊、表格、引用、程式碼、連結、圖片、`[[wikilink]]`。不支援 HTML 標籤（會被當成文字）。
- `[[頁面|顯示文字]]` 在表格裡也能用。

## 6. 檔案命名與放置

| 東西 | 位置 |
|------|------|
| 攻略內容 | `wiki/<分類>/<頁面名稱>.md` |
| 建置程式 | `web/build.py`、`web/md.py` |
| 樣式、前端程式 | `web/static/style.css`、`web/static/app.js` |
| 產出的網站 | `docs/`（**禁止手動修改**） |

- 頁面網址：`docs/p/<檔名>.html`，空白換成 `-`。兩頁轉換後同名時，建置會報錯。
- 新增分類資料夾時，在 `build.py` 的 `CATEGORY_LABELS` 加中文名稱；新增頁面類型時，在 `TYPE_LABELS` 加中文名稱。

## 7. AI 修改規則

1. **只用 Python 標準函式庫與原生 HTML／CSS／JavaScript**，不引入框架、npm 或 CDN。
2. **全部使用相對路徑**，網站要能用 `file://` 開啟，也要能在 GitHub Pages 子路徑運作。
3. **安全**：所有文字都要 HTML escape，不執行內容中的 HTML 或 script。
4. **不使用網路圖片**（版權）；只能顯示 `raw/assets/` 裡使用者自己拍的照片。
5. **localStorage 只記深淺色模式**，讀寫包在 try/catch 裡。
6. 修改 `md.py` 後，要確認所有既有頁面重新 build 後仍正常顯示。
7. 不要為了網站好看而改 `wiki/` 的內容或結構。

### 每次修改後的檢查

1. `python web/build.py` 沒有錯誤，並回報斷鏈。
2. 打開 `docs/index.html` 檢查：首頁、一個分類頁、內容最多的攻略頁、搜尋、深色模式、手機寬度。
3. 在 `wiki/log.md` 追加 `## [YYYY-MM-DD] web | 修改內容`。
4. `web/` 與 `docs/` 一起 commit。
